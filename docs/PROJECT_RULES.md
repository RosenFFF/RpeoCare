# 项目专属规则

入口为工作区设置的“项目专属规则”，Issue 与 PR 详情提供直接链接。规则按账户和仓库保存在服务端，由 `src/server/workbench/policy.ts` 管理；共享结构与判断位于 `contracts/policy.ts`、`shared/lib/project-policy.ts`。

## 候选与确认

读取候选固定当前分支提交，检查最多八个支持的 README、CONTRIBUTING、Issue 模板和项目清单，不调用模型、不写 GitHub、不自动启用。模板字段的必填性和适用范围由维护者核对。

编辑后保存候选，原有效版本继续使用。维护者勾选已核对并确认后启用；确认时重新验证仓库来源的固定提交、路径、行号及原文。手动规则标为维护者约定。最多二十四条，保存并确认空规则集可以停用现有约束。

保存和确认有版本比较，防止并行页面覆盖。确认版本独立保留，旧分析不会被改写。规则适用于整个仓库，当前没有分支覆盖规则集。

## 规则含义

| 类型 | 判断与边界 |
| --- | --- |
| Issue 必填信息 | 运行时、平台、复现步骤、预期和实际行为，可限定问题类别。原始反馈中的线索可核对，缺少时请求确认补充 |
| 支持版本 | 例如 `Python \| 3.10 \| 3.11`，仅支持版本前缀列表。范围外提示核对，未知保留未知，不自动关闭 |
| 标签分类 | 精确匹配标签。多个映射冲突进入人工核对，不覆盖人工最终判断 |
| PR 必须检查 | 精确匹配检查名称，旧式 Status 含 `Status:` 前缀。成功、失败、进行中、缺失或未读取分别处理 |
| PR 测试变更 | 检查非删除的测试路径；不证明覆盖充分或测试通过 |
| 验证命令 | 提供维护者确认过的命令约定，不自动执行 |
| 维护约定 | 提供模型和人工参考，不伪装为确定性通过或失败 |

## 分析与来源

Issue 将有效规则加入模型上下文。服务端核对提取的原文引用，并执行字段、版本与标签规则；必填信息未提取到时限制准备度并建议补充，人工已确认的处理状态优先。

Issue 回复草稿携带规则版本，版本变化后须重新分诊或生成，发布时再次校验。

PR 分块任务固定规则版本，汇总按采集快照计算检查结果。规则变化后，运行任务、失败重试和草稿交付都会要求重新审查。详情展示规则名称、结果、原文线索、固定提交来源或手动约定。

仓库来源是历史快照，后续文件变化不会自动改写规则。维护者需重新读取并确认。pi 调查提供 `read_project_rules` 工具；返回的 `policy` 证据不当作已读取源码。

接口校验同源、当前仓库与会话归属。规则和引用不改变 Agent 权限，不触发命令执行或 GitHub 发布。原文匹配只证明引用存在，语义判断仍需人工核对；准备度不是校准概率，效果需另行评测。
