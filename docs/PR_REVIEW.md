# PR 证据化审查（2026-10-01）

## 旧模块审计

真实入口 `/pull-requests` 使用 `GitItems kind="pulls"`。改造前只展示开放列表和原始 patch，再通过模型生成自由文本 Review 草稿。`features/pull-requests/pull-requests-view.tsx` 是未接入的静态演示，不代表真实功能。本轮只升级真实链路。

## 可用流程

1. 连接真实 GitHub 仓库，打开 PR。
2. 服务端读取 head/base SHA、最多前 100 个变更文件、单文件最多 12,000 字符 patch，并显式标记截断。
3. 读取当前 head 对应 Check Runs 和旧式 Commit Status；读取失败、等待执行、已完成失败、空清单分别显示，不推断通过。
4. 对描述中的同仓库 `Fixes/Closes/Resolves #N` 最多读取 3 条关联 Issue。关联仅是声明，不证明修复了需求。
5. 配置模型后点击 AI 审查，输入 patch 总预算 45,000 字符。保留读到的代码行，不把半行当成证据。
6. 模型返回中文摘要、最多 12 个结构化发现、置信度与限制；格式校验失败最多修复一次。模型配置快照固定到本次调用，并记录模型 ID/版本和提示版本。
7. 服务端把文件路径、行号、LEFT/RIGHT 和引用片段与实际 Diff 校验。无证据的发现降为低置信度信息线索，禁止直接确认发布。**引用存在只证明引用不是捏造，不证明 AI 的语义判断必然正确。**
8. 维护者逐项确认或忽略，也可撤回判断；通过 review ID 和 revision 防止多页旧判断覆盖新结果，按账户、仓库、PR 隔离并记录历史。
9. 全部线索处理完后勾选理解审查边界，生成可编辑的 Review 草稿。只包含被保留且证据可核实的发现，不让模型再次自由生成、重引入忽略项。
10. 在规范改进中编辑、下载，明确确认后发布 GitHub COMMENT。生成和发布时校验提交、审查版本和 Diff/描述指纹；不自动 APPROVE、REQUEST_CHANGES 或合并。

## 一致性与边界

- GitHub PR files 接口是可变列表，因此采集前后比对 head/base/更新时间；模型返回后再次比对。发生更新时不保存混合版本结果。
- 模型结果按 head/base、描述及输入 Diff 指纹缓存，同版本读取刷新 CI，不消耗第二次模型调用；强制分析生成新报告，旧报告保存在审查事件历史。
- 测试/文档路径识别是规则信号，不代表覆盖率或测试执行。
- 可见 CI 通过不等于全部必需检查通过，也不是可合并性结论。
- 大 PR、二进制、缺失/截断 patch、模型预算遗漏均明示。未读取文件不能判定无问题。
- 不克隆或执行 PR 代码，无 Docker 前置要求。不运行 fork 中代码、安装脚本或 CI workflow。
- 不做全仓库静态分析、自动修复、自动合并、全量行内评论，也不提供经过真实样本验证的正确率承诺。
- 评论始终以维护者审阅为前提；模型/仓库内容是不可信数据，React 以文本呈现代码和输出。

## 验证

测试使用临时 SQLite、mock GitHub 与 mock 模型，不消费真实付费额度或实际发布评论。覆盖 Diff 坐标、伪造证据降级、模型预算、CI 三态、快照变化、账户隔离、修复重试、人工决定、草稿和过期发布拦截。浏览器覆盖 PR 列表、失败 CI、确认发现、生成草稿、历史、过期状态和 390px 适配。

实际模型输出质量、OAuth 权限和真实 GitHub COMMENT 发布仍需要维护者授权的测试仓库验收。本轮不声称已经节省多少时间或达到多少审查准确率。


## 页面布局

- PR 列表与详情使用上下堆叠布局，不再让右侧详情面板把左侧短列表拉成同高空白栏。
- PR 列表采用响应式卡片网格：少量 PR 按内容高度收缩，多条 PR 自动平铺。
- 选中 PR 后详情在列表下方展开；移动端保持单列。
- 空状态保留 Review Protocol 引导，说明固定提交、核对 Diff/CI、确认后生成草稿。
