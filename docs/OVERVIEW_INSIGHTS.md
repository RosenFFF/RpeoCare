# 项目概览的维护观测

维护观测在项目概览中展示检查结果构成、类别分布、历史快照和最多三项后续事项。完整检查清单及文件依据位于体检报告页；概览中的图表和事项可以带筛选条件打开报告。

概览首屏先显示项目状态与贡献路径的主要操作。项目维护地图位于可折叠区域，只有展开时才挂载3D展示，避免隐藏图形占用渲染资源和推迟主要操作。现有全局主题、报告依据和历史观测保持一致。

## 数据与交互

- 结果环图使用当前报告的已通过、待完善和无法判断数量。图例按钮与扇区切换状态筛选，环内显示选中状态的数量；未选择时显示全部检查数量。
- 类别条形图按文档、协作、工程排列，使用共同刻度和零起点。点击类别筛选后续事项，点击色块同时选择类别与状态；图表保留整体数据供比较。
- 后续事项先展示待完善，再展示未知结果，最多三项。这是展示顺序，不是风险评级。选择已通过状态时可以查看通过项。重置按钮清除图表筛选。
- 报告链接通过 `run`、`tab=report`、`category`、`status` 和 `check` 参数恢复报告、类别、状态和展开项。切换到另一任务或新建任务时清除前一报告的检查筛选。
- 未知结果使用斜线纹理和文字共同表达，不计为失败，也不转换为零。环图比例仅描述检查构成，不提供综合质量分数。

## 历史边界

`getOverview` 按账户、当前仓库地址和所选分支查询最近十二份成功报告，按任务创建顺序展示。历史与当前报告使用同一项目查询条件，失败、取消或仍在执行的任务不会替代成功报告。历史查询只读取报告，不调用 GitHub 或模型，不创建体检任务。

每个快照返回报告标识、提交、生成时间、三类状态数量、总检查数量、AI 分析状态，以及由检查标识、类别和来源组成的比较口径。接口不返回历史报告正文或文件依据；打开对应报告后再读取详情。

趋势使用阶梯线和明确的数据点连接相邻快照，横轴代表任务顺序，不表示连续时间采样。有一个快照时只展示一个点；没有历史数据时显示提示。展开数据表可逐次核对准确数值并打开报告。

只有全部展示快照的检查口径和 AI 分析状态一致时，界面才显示当前指标相对首个快照的数量变化。口径不同时显示差异提示，不推断改善幅度。未知指标使用虚线，所有指标均保留准确数量和文字标签。

## 实现与验证

`features/overview/overview-insights.tsx` 负责图表与局部筛选，Recharts 负责环图和趋势图，原生按钮组成类别条形图。图表模块通过 Next.js 动态导入，与其他工作台视图分开加载。样式复用现有主题变量，支持深色主题、窄屏和减少动态效果偏好。图例、类别和趋势指标可通过键盘操作；历史数据表提供图形之外的读取方式。

历史接口测试位于 `tests/workbench/overview.test.ts`，覆盖账户、仓库、分支隔离，十二份上限，成功报告顺序，空检查，未知状态和不同分析口径。浏览器验收使用隔离的只读报告副本及明确标注的合成边界数据，不向实际工作区接口注入测试数据。
