# 规范改进与草稿审阅

## 定位与布局

模块使用“草稿与交付”入口，内部明确分为文档改进、Issue 回复和 PR 评论。它是当前项目的草稿审阅中心，不是完整仓库文档资产目录。

列表支持当前项目全量分类、状态与搜索，服务端先筛选再分页，返回准确数量与下一页标记。默认按类型、目标和分支收起筛选范围内的旧生成草稿，可展开查看；列表注明标题、来源、分支和创建日期。发布租约过期的记录按待核对状态参与筛选。点击草稿进入全宽编辑，返回保持筛选；提供草稿切换、来源折叠、版本记录和发布后状态。加载、读取失败和无草稿分别展示。空状态随分类提供下一步，文档生成区仅在全部/文档分类出现，无可生成项时收为提示；无须分页时隐藏翻页。详情在交付按钮前列出未保存、检查阻断、归档、交付状态或缺授权原因；GitHub 设置直达对应模块并返回原草稿。体检入口定位生成区，Issue/PR 生成后提供具体 draftId 的审阅链接；返回讨论按 number 深链接定位。

## 编辑可靠性

- 临时编辑按 draftId 保存在内存和当前标签页 sessionStorage，切换草稿不会清空；成功保存才删除临时缓存。
- 离开/刷新/切换项目有未保存提示；缓存不可用时提示保存或下载，不承诺永久保存。
- 编辑携带开始编辑的 revision，远端版本变化时拒绝覆盖，保留本地内容供比较。
- 已保存内容变更、恢复和状态变更在 SQLite 留存版本；UI 展示当前加最近 20 个历史版本，恢复复制内容为新版本，不改写旧记录。
- 新一轮生成保留为新草稿，以 previousDraftId 关联同目标/分支的上一份，不自动覆盖维护者编辑。可归档与取消归档，无不可恢复删除。

## 差异与预览

使用 jsdiff 行级比较，替换正确计入增删行，显示行号/正负符号，默认折叠远离修改的上下文；可展开全文或与保存版本比较。算法有限时/编辑距离/输入大小约束，超限明确不显示虚假统计。

使用 react-markdown + remark-gfm 支持链接、列表、表格和代码块。禁用原始 HTML，不自动加载外部图片；相对文档链接指向 GitHub 分支文件，而非 RepoCare 站点；默认 URL 安全转换保留。

## AI 与静态校验边界

仅用户点击生成时调用已配置模型，快照上下文有界，原文完整性不足拒绝替换草稿。文档必须来自当前项目/分支最近成功报告，查询不依赖前 20 个任务分页。其他分支草稿可编辑下载；发布文档目前仅支持默认分支，服务端拒绝非默认分支而不悄悄更改目标。

内容检查区分阻断（空内容、过长、疑似凭据、危险链接协议）、提醒（占位符、缺失相对目标、配置中未出现的 npm 脚本、标题/版权移除、明显缩短）和未验证（外部链接、快照不足、未执行命令）。这些是有限静态规则，不证明文档语义正确，也不是全面秘密扫描。发布时服务器再次核验阻断项；警告需要维护者审阅确认。无 Docker/代码执行/付费额外服务前置。

## 单文件及小批次交付

- 发布操作明确为创建 Draft PR、发布 Issue 回复、发布 PR COMMENT，不批准或合并 PR。
- 2–4 个文档可组成一个 PR，必须同仓库、同分支、同 SHA、不同允许路径，版本均匹配且非归档/非已发布。
- 每个草稿锁及共享操作锁防并发；SQLite 批次状态原子迁移，发布整体网络预算 100 秒，小于锁租约。
- 先校验实际 push 权限、默认分支和远程 SHA，再创建多个 blob、单 tree、单 commit、独立 ref、单 Draft PR，永不更新默认分支。
- 发布前置条件失败恢复待审阅；写请求后网络异常统一进入待核对，禁止自动重发；只读核对可找回匹配分支 PR 地址，但不会仅凭元数据把不确定内容宣称为已发布。

## 后续验证

读取 GitHub PR 开放/关闭/合并状态与体检验证分开显示。只有当前成功报告的提交等于合并提交或 GitHub compare 证明包含该提交，且对应检查项存在，才展示通过/仍待完善。它只表示关联检查结果，不表示所有问题已解决。状态核对不会自动创建体检任务；体检仍需主动发起。

## 验收边界

单元/集成使用临时 SQLite、mock 模型/GitHub，不付费、不真实发布。浏览器模拟数据验证交互和布局，真实权限、PR 创建、组织策略和外部模型仍需专用测试仓库验收。

安装依赖时 npm audit 仍报告既有 Next/pi/concurrently 等依赖链的 high/critical 告警；新增 diff/react-markdown/remark-gfm 未出现在当前 audit 列表。本轮未执行破坏性 audit fix --force 或跨版本框架迁移，公网前应单独治理，不能宣称依赖安全审计通过。

评论交付核对会只读获取对应 Issue comment / PR review 并比较已保存内容；无法取得远程标识、正文变化或未知发布结果时明确要求人工核对，不伪造“远端检查通过”。
