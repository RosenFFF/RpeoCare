# 项目概览

项目概览是工作区的首页：最上方是 3D 项目维护地图，下面依次是近期维护记录、项目概况指标和维护观测图表。它回答两个问题——项目现在的维护状态如何，以及接下来该处理什么。

## 页面会随进度变化

| 项目状态 | 概览显示 | 建议操作 |
| --- | --- | --- |
| 尚未连接项目 | “从一个真实项目开始维护”和三步维护流程 | 点击“连接 GitHub 项目” |
| 已连接，尚无体检报告 | “项目已连接，下一步建立可信快照” | 点击“开始项目体检” |
| 体检正在进行 | “项目体检正在进行中” | 点击“查看执行进度” |
| 已有成功报告 | 完整的概览（下文各节） | 按“接下来，处理这些事”逐项处理 |

概览始终展示**最近一份成功的体检报告**。如果最新一次体检仍在进行、已取消或未完成，顶部会提示“当前展示上一份成功报告”，原报告不会被覆盖。

## 项目维护地图

页首的 3D 地图把体检、Issue、PR 和草稿四个模块放在同一个场景里，每个节点显示对应的待处理数量（例如“3 项基础待完善”“12 条反馈待整理”）。

- 拖动可以旋转场景，点击节点查看该模块的说明并进入对应页面。
- 右上角可以暂停或继续场景动效、复位视角。
- 浏览器无法使用 WebGL 时会显示简洁视图，信息相同；系统开启“减少动态效果”时，场景默认暂停动效。

地图下方的标题行显示仓库全名、分支和报告对应的提交短 SHA；点击“重新体检”会开始新的体检任务。

## 接下来，处理这些事

“继续维护”面板列出当前项目的近期记录，可以按 **需要处理 / 等待审阅 / 进行中 / 已有结果** 筛选。点击一条记录回到对应页面继续处理；打开记录不会自动执行任务或调用模型。

面板中的“使用条件”会说明三类能力当前是否可用：

- **AI 调查**：是否已有默认模型，以及调查服务是否在线。已有默认模型不代表连接一定可用，需要在设置中主动测试。
- **GitHub**：公开仓库可直接读取；私有仓库和发布需要相应授权。
- **隔离执行**：执行服务是否已启用。具体依赖和 Docker 状态仍要在每个任务的预检中确认。

> [!NOTE]
> “已有结果”只表示任务保存了结果，不代表候选补丁已经通过全部测试。

## 项目概况

五个指标卡片，点击可以进入对应页面：

| 指标 | 含义 |
| --- | --- |
| 维护基础 | 本次报告中“已通过”的检查数 / 检查总数，并显示待完善数量 |
| Issue 分诊 | GitHub 当前开放的 Issue 数 |
| PR 检查 | GitHub 当前开放的 PR 数 |
| 草稿与交付 | 待确认的文件草稿数量 |
| 贡献路径验证 | 最近一次贡献路径验证的状态，例如“路径已走通”“计划待确认”“需要重新验证” |

Issue 和 PR 数量是实时读取的 GitHub 数据，与报告的提交无关；读取失败时会显示“部分 GitHub 数量暂不可用”，可以点击“重新读取”，报告本身不受影响。

## 维护观测

页面底部的图表帮助你从整体状态定位到具体检查项：

- **检查结果构成**：本次固定提交的检查按“已通过 / 待完善 / 无法判断”的构成，点击可筛选。
- **维护基础分布**：按文档、协作、工程三个类别比较，所有柱形使用同一刻度、从 0 开始。点击色块查看该类别的结论。
- **接下来处理**：先列待完善项，再列需要核实的未知项，点击进入完整报告。
- **维护变化**：当前仓库与分支的历次体检快照，每个点对应一份真实报告，折线只连接相邻快照。

> [!TIP]
> 比较趋势时注意每个点的检查范围：基础规则体检和包含 AI 内容分析的体检检查项数量不同，图表会提示“检查范围或 AI 分析状态不同，数量仅供逐次查看”。

## 常见问题

**为什么概览的数字和体检报告不一样？** 维护基础来自报告的固定提交；Issue 和 PR 数量是当前 GitHub 实时数据。两者时间点不同。

**切换项目后概览没有变化？** 刷新页面，并确认侧栏顶部的项目名称。概览、报告、Issue、PR 和草稿都按当前项目展示。

**没有任何记录？** 先完成一次[项目体检](audit.md)，概览会自动更新为真实项目数据。
