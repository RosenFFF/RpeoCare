# 参考与功能边界

本章用于解释界面词汇、结果状态和适用范围。产品操作说明对应仓库内的工作区、任务队列和交付实现；深入部署或开发时可继续阅读下方技术资料。

## 常用术语

| 术语 | 含义 |
| --- | --- |
| 快照 / SHA | 固定的 Git 提交版本；使报告与证据可以复查 |
| base / head | PR 的合并目标与待合并改动版本 |
| Diff | 相对于基线的文件改动内容 |
| Worker | 在后台处理队列任务的进程 |
| Runner | 执行经确认的验证计划的隔离环境 |
| 草稿 / Draft PR | 尚待审阅的内容或 GitHub 草稿合并请求，不表示已合并 |
| COMMENT | 提交评论型 PR 审阅，不等于批准或请求修改 |
| 对照验证 | 对基线与候选应用共享测试，比较目标行为和回归结果 |

## 如何理解状态

| 状态或提示 | 含义与操作 |
| --- | --- |
| 排队 / 运行中 | 等待 Worker 或正在处理；先查看状态再决定是否重试 |
| 完成 | 本任务处理结束；仍需检查结论、覆盖范围与证据 |
| 部分完成 / 未审范围 | 有失败或未覆盖内容，不能作为完整审查 |
| 过时 | 来源版本变化，需要按新提交重新检查 |
| 环境受阻 | 执行环境没有满足条件，不是对业务行为的判定 |
| 草稿 / 发布中 | 内容尚未交付，或正在向 GitHub 提交 |
| 结果待确认 | 不能确定远端写入结果，先核对 GitHub 再操作 |
| 已发布 / 已归档 | 已交付或从日常待办中归档；通过来源记录继续追溯 |

## 当前适用范围

- 仓库平台为 GitHub；不能把 GitLab 或 Gitee URL 作为已支持入口。
- 常规体检读取固定快照，不自动执行被检查仓库代码。
- 模型发现、修复候选和文档建议均需要人工核对。
- 隔离复现针对公开 GitHub HTTPS 仓库；贡献路径和需求对照只覆盖经过计划选择的步骤。
- PR 审查航道的阶段只来自已保存的审查快照，横向位置只表示距上次更新的时间，不代表风险或优先级。
- 发布动作需要明确确认；不会自动合并 PR。
- 当前部署基于同机共享 SQLite，不提供开箱即用的跨机器分布式队列。
