# 快速开始

本章带你完成“连接一个 GitHub 仓库，得到并阅读一次体检报告”。这条路径不要求发布内容，也不要求启用 Docker。尚未运行服务时，先完成[部署与运维](deployment.md)。

## 准备条件

- 一个可以访问的 RepoCare 实例。
- 一个真实 GitHub 仓库地址，例如 `https://github.com/组织名/仓库名`，以及要检查的分支。
- 如果实例要求登录，先完成登录；私有仓库还需要在工作区设置中授权 GitHub 仓库访问。
- 基础规则检查不需要模型；需要内容研判或草稿生成时，先完成[模型连接](configuration.md)。

## 连接仓库

1. 打开“项目概览”，通过项目选择入口连接仓库。
2. 输入仓库地址，核对仓库所有者、仓库名和分支后确认。
3. 确认工作区显示的是目标仓库。切换项目后，报告、Issue、PR 和草稿均应按新项目查看。

**预期结果**：概览显示真实项目资料和维护入口。若读取失败，先检查地址、分支和访问权限，见[连接排查](troubleshooting.md)。

## 完成第一次体检

1. 进入“项目体检”，核对当前项目与分支，开始体检。
2. 等待任务进入运行状态。后台会固定本次提交快照，后续证据基于这个版本。
3. 完成后打开报告，先看检查项与问题，再展开相关文件证据。
4. 导出 Markdown 或 JSON 报告，保留本次检查结果。

**预期结果**：得到带检查结论与证据的报告。报告描述的是本次快照；仓库后来有新提交时，应重新体检。排队不结束时，先查后台 Worker，不要连续创建重复任务。

## 生成并保存第一份草稿

1. 配好默认模型后，在“草稿与交付”选择成功报告中可改进的检查项，生成对应文档草稿。
2. 打开草稿，核对来源证据和目标文件；在编辑、预览和 Diff 之间切换。
3. 修改不准确的内容并保存，或下载交给其他维护者审阅。

**预期结果**：得到可继续编辑的草稿。生成和保存不会自动写回 GitHub。如果没有可用检查项，不必为了走通流程人为制造问题，可转到 Issue 或 PR 进行审阅。

## 下一步

需要处理具体协作任务时，阅读[模块操作指南](modules.md)；需要完整维护案例时，阅读[工作流与最佳实践](workflows.md)。首次体验建议在保存草稿后停下，确认理解发布目标和权限，再进行实际交付。
