# 快速开始

本章带你走完一条最短路径：连接一个 GitHub 仓库，完成第一次体检并读懂报告，再生成并保存第一份文档草稿。全程约 15 分钟，不会向 GitHub 写入任何内容，也不需要 Docker。

## 开始之前

| 需要准备 | 说明 |
| --- | --- |
| 一个可访问的 RepoCare 实例 | 还没有运行时，先按[部署与运维](deployment.md#本地启动)启动，默认地址是 `http://127.0.0.1:3000`。 |
| 一个 GitHub 仓库 | 公开仓库可以直接使用，不必是你自己的项目。私有仓库需要先[追加仓库授权](settings.md#github-账户与授权)。 |
| （可选）一个模型连接 | 基础规则体检不需要模型；内容研判和草稿生成需要。可以稍后在[模型连接](settings.md#配置模型连接)中添加。 |

> [!TIP]
> 只是想看看效果？在体检页点击“试填示例仓库”，用示例公开仓库走一遍即可。

## 第 1 步：连接项目

在首页点击“进入工作台”。根据你的登录方式，第一屏会不同：

- **已用 GitHub 登录**：显示“选择要维护的项目”。从“我的仓库”或“我有权访问的仓库”中选择，或切换到“粘贴仓库地址”，然后点击“连接”。列表按最近更新排序，每页最多 30 个，搜索只作用于当前页。
- **未用 GitHub 登录**：直接打开“项目体检”的新任务。在第 2 步填写仓库地址并开始体检，该仓库会同时成为当前项目。

连接只保存当前项目，不会自动体检、调用模型或发布内容。之后可以点击侧栏顶部的项目名称随时切换项目。

**完成后**：侧栏顶部显示项目名称。

## 第 2 步：完成第一次体检

1. 进入侧栏“项目体检”，填写或核对 GitHub 仓库地址。分支留空时使用仓库的默认分支，需要时可以填写其他分支。
2. 查看表单下方的模式提示：
   - 显示“基础规则模式”表示没有可用模型，本次只做规则检查；
   - 已配置默认模型时，会额外进行内容研判。
3. 点击“发送仓库，开始体检”。任务依次经过 **读取仓库 → 收集文件 → 规范检查 → 内容研判 → 生成报告** 五个阶段，左侧执行轨迹会实时更新。
4. 完成后点击“打开完整报告”。

> [!NOTE]
> 体检开始时会锁定一个提交（SHA）。报告中的每条证据都对应这个版本；仓库之后有新提交，请点击“重新体检最新提交”。

**完成后**：你会得到一份包含 8 项规则检查（启用模型时另有 3 项内容研判）的报告。

## 第 3 步：读懂体检报告

报告顶部是检查结果构成，下方是“维护检查清单”。

1. 先用状态筛选查看 **待完善** 的检查项，每一项都有结论、来源文件和改进建议。
2. 展开“规则检查依据”或“内容研判依据”，核对引用的文件路径和原文片段。
3. 再看 **无法判断** 的项目：它表示证据不足（例如子项目结构复杂），不等于有问题，也不等于通过。
4. 需要留存时，导出 Markdown 或 JSON 报告，文件名包含仓库名和提交短 SHA。

> [!IMPORTANT]
> “已通过”只表示在本次提交中找到了对应文件或配置，例如“持续集成”通过不代表 CI 正在通过，“测试入口”通过不代表测试能跑通。报告不是项目质量评分。

## 第 4 步：生成第一份草稿

这一步需要[默认模型](settings.md#配置模型连接)。

1. 在报告页点击“生成改进草稿”，或进入“草稿与交付”，在“从体检问题生成文档改进”中选择一个待完善项。
2. 生成完成后打开草稿，在 **编辑 / 预览 / 差异** 之间切换，核对来源证据和目标文件。
3. 删去模型猜测的内容（不存在的命令、地址或功能），修改后点击“保存”。

**完成后**：草稿以“待审阅”状态保存在项目中，可以继续编辑或下载。生成和保存都不会写回 GitHub。

> [!TIP]
> 报告里没有可生成草稿的待完善项时，不必为了走通流程人为制造问题。可以转到 [Issue 分诊](issues.md)为一条反馈准备回复。
