# 模块操作指南

工作区围绕当前项目组织内容。开始操作前，先核对顶部或侧栏的仓库与分支，尤其是在多个项目之间切换后。

## 项目概览

**作用**：了解项目现状，找到最近的任务和待处理事项。3D 维护地图提供导航，任务记录和通知用于回到具体处理页面。

1. 连接或选择项目，核对仓库信息。
2. 查看近期任务和维护状态，进入对应报告、Issue、PR 或草稿。
3. 切换项目时重新确认上下文。

**结果**：找到下一项维护工作。地图和统计是导航信息，具体判断应打开任务证据核对；没有记录时，先运行一次体检。

## 项目体检

**作用**：检查固定提交上的项目资料和协作规范，输出可追溯报告。基础检查无需运行仓库代码；内容研判需要模型。

1. 核对分支后开始体检，观察排队和运行状态。
2. 完成后打开检查项，阅读结论、来源文件和建议。
3. 导出 Markdown/JSON，或将可改进检查项交给草稿生成流程。

**结果**：固定快照的体检报告。取消后查看实际任务状态；需要重试时创建重试任务，不要将旧报告当作新提交的结论。

## 贡献路径验证

**作用**：检查新贡献者能否按项目资料完成选定的安装、测试或检查路径。入口位于项目体检相关页面。

1. 从成功体检快照提取 README、CONTRIBUTING 和项目清单中的命令。
2. 审阅工作目录、依赖、命令和预期结果，确认没有误解项目说明。
3. 在隔离执行环境就绪后确认执行，查看每一步日志与结果。

**结果**：选定贡献路径的执行证据。依赖安装失败先处理环境；单条路径通过不代表整个项目的全部构建和测试通过。

## Issue 分诊

**作用**：从 Issue 原文和项目证据整理问题类型、缺失信息及处理建议。

1. 从问题地形图或列表选择 Issue，阅读原文；列表筛选、分页后再定位目标。
2. 主动开始分诊，核对模型引用的源码、规范和推断。地图中的初步分类线索不等于完成 AI 分诊。
3. 根据实际情况调整结论，生成回复草稿，到“草稿与交付”审阅。
4. 对需要深入调查的条目进入维护调查；Bug 可进一步准备复现计划。

**结果**：分诊建议、证据及可编辑回复。信息不足时先向报告者索取环境、输入与复现步骤；没有复现成功不能直接认定 Issue 无效。

## PR 检查

**作用**：结合 Diff、CI 状态、项目规则和源码证据检查改动。

1. 在分支导航中选中分支，查看完整名称及提交；“展开 PR”筛选的是合并目标分支（base）。星图不是分支血缘图。
2. 从 PR 图或列表进入详情，先读 Diff 和检查状态。未知或尚未返回的 CI 状态不等于通过。
3. 进入 PR 审查，主动开始 AI 审查。任务固定 head/base 提交并分块处理，离开页面不会自动取消后台审查。
4. 查看完成范围、失败块与未审范围。仅对失败块重试可以保留已完成结果；有新提交时需重新审查。
5. 人工筛选可信发现，再生成评论草稿。

**结果**：带源码坐标和覆盖范围的审查发现，以及可审阅的 COMMENT 草稿。完成状态不代表改动正确，也不代表测试通过；产品不会自动批准或合并 PR。

## 维护调查与对照验证

**作用**：在具体 Issue、PR 或报告上下文继续读取证据，准备候选补丁及验证计划；它不是独立的全自动修复页面。

1. 明确本次要验证的需求和预期行为，让调查围绕一个具体问题展开。
2. 核对候选补丁、原文要求和共享测试；下载补丁时先人工审阅。
3. 对支持的任务准备基线版本与候选版本的对照计划，确认依赖和执行范围后提交隔离运行。
4. 对照目标断言、普通回归与环境错误，导出证据。

**结果**：候选方案和适用范围内的对照证据。预检只检查计划条件，不等于已执行测试；当前对照能力以支持范围内的 Python/pytest 场景为主，不能承诺任意项目一键验证。

## 草稿与交付

**作用**：集中管理文档改进、Issue 回复和 PR 评论，在发布前完成最后审阅。

1. 按类型、状态、分支筛选或搜索当前项目草稿；需要旧版本时打开历史版本显示选项。
2. 打开草稿，核对来源、目标、内容和证据。文件类草稿可编辑、预览与查看 Diff。
3. 保存修改。遇到版本冲突先比较已保存版本，避免覆盖其他修改；离开前处理未保存内容。
4. 选择下载，或在权限满足后确认发布。文件草稿创建独立分支上的 Draft PR；Issue 回复写入评论；PR 发现发布为 COMMENT 审阅。
5. 发布后通过返回的 GitHub 地址核对目标与内容。若状态为结果待确认，先核对远端，避免重复发布。

同一分支的文件草稿可按界面提供的批量交付能力合并为一个草稿 PR。目标提交变化时，先更新或重新生成草稿再审阅，不要强行沿用旧 Diff。

## 工作区设置与使用指南

**作用**：管理外观偏好、GitHub 账户、模型连接和项目规则。集成能力展示区用于说明能力，并不是后台服务的启停开关。

按[账户与配置](configuration.md)完成连接后回到原任务。“使用指南”提供常见工作路径和完整产品文档入口。可通过 Ctrl/⌘ + K 打开页面搜索；它用于工作区页面跳转，不是仓库内容全文检索。
