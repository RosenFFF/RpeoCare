# 功能总览

工作区围绕“当前项目”组织：左侧是维护流程导航，中间是当前页面，所有数据都属于侧栏顶部显示的那个项目。本页介绍界面布局和各页面的分工，以及所有页面共用的操作约定。

## 工作区布局

| 区域 | 内容 |
| --- | --- |
| 侧栏顶部 | 项目切换器，显示当前项目名称；点击后可连接或切换仓库 |
| 维护流程 | 按“项目 → 协作审阅 → 交付”分组的页面导航 |
| 侧栏底部 | 工作区设置、使用指南（打开本手册）和当前会话身份 |
| 顶部栏 | 当前位置、项目连接状态、快速跳转、日夜模式切换、工作区动态通知 |

侧栏可以通过顶部栏左侧的按钮收起；在窄屏上，侧栏收进左上角的菜单按钮。

## 页面分工

| 分组 | 页面 | 解决的问题 |
| --- | --- | --- |
| 项目 | [项目概览](overview.md) | 项目现在的维护状态如何？接下来该处理什么？ |
| 项目 | [项目体检](audit.md) | 文档、协作模板和工程配置缺了什么？证据在哪？ |
| 项目 | [贡献路径验证](contributor-path.md) | 新贡献者按文档操作，能否真正装好依赖并跑通测试？ |
| 协作审阅 | [Issue 分诊](issues.md) | 哪些反馈最该先处理？信息是否完整？该怎么回复？ |
| 协作审阅 | [PR 检查](pull-requests.md) | 哪些变更卡住了、卡了多久？改动里有什么问题？ |
| 协作审阅 | [维护调查与对照验证](maintenance.md) | 这个问题该怎么修？修复前后的测试结果是否不同？ |
| 交付 | [草稿与交付](drafts.md) | 回复、评论和文档改进是否准确？可以发布了吗？ |
| 设置 | [工作区设置](settings.md) | 用哪个模型？有没有 GitHub 写入权限？项目有哪些约定？ |

贡献路径验证位于项目体检页面内的“贡献路径”标签；维护调查从具体的 Issue、PR 或体检报告中进入，不是独立的侧栏页面。

## 通用操作约定

**快速跳转**：在工作区按 `Ctrl` + `K`（macOS 为 `⌘` + `K`），输入页面名称（中文或英文均可，例如“体检”“Issue”）跳转。它只用于切换工作区页面，不搜索仓库内容；搜索本手册请在文档页按同样的快捷键。

**筛选只作用于当前页**：Issue、PR 和仓库列表都分页读取（每页最多 30 条）。搜索框和筛选只在已加载的这一页中查找，找不到时先翻页或调整筛选，不要立即判断数据丢失。草稿搜索例外，它覆盖当前项目的全部匹配草稿。

**主动发起，才会调用模型**：打开页面、读取文件与检查、保存设置都不调用模型。只有“开始 AI 分诊”“开始 AI 审查”“生成草稿”这类由你点击发起的操作才会调用，维护调查等页面还会在按钮旁提示“此操作会调用已配置模型”。

**确认后才写入 GitHub**：修改 Issue 状态、标签或指派人，发布回复、评论或 Draft PR，都会先弹出确认，说明将要写入的内容和目标。

**未保存提示**：草稿和模型表单在有未保存修改时，切换项目或离开页面会先询问。草稿编辑内容会尽量暂存在当前标签页。

**状态颜色**：页面使用统一的语义颜色——青色表示主题与进度，琥珀色表示需要留意（进行中、待补充、已过期），红色表示失败或高风险，灰色表示未知或未开始。颜色总是配合文字说明，不单独表达含义。

## 工作区动态

顶部栏的铃铛图标打开“工作区动态”，列出当前项目近期的体检、调查、验证和草稿记录。有未读动态时图标上会出现小圆点；打开后会标为已读，已读状态只保存在当前浏览器。点击某条动态可以回到对应页面继续处理。

## 日夜模式

顶部栏的月亮 / 太阳图标切换日间和夜间配色。选择保存在当前浏览器，工作区、首页和本手册共用同一设置。
