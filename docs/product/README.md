# RepoCare 使用手册

RepoCare 是面向 GitHub 开源项目维护者的工作台：在固定提交上体检项目资料，按证据分诊 Issue、审查 PR，把建议整理成可编辑的草稿，最后由你确认交付。本手册说明每个页面怎么用、结果怎么理解，以及部署和配置方法。

## 一次维护的完整路径

1. **连接仓库**：选择 GitHub 仓库与分支，建立本次工作的上下文。
2. **固定快照并体检**：后台锁定一个提交，检查文档、协作模板和工程配置，所有引用都指向这个版本。
3. **审阅协作内容**：在 Issue 分诊和 PR 检查中阅读原文、证据和 AI 建议，记录你的判断。
4. **按需验证**：在隔离的 Docker 环境中复现 Bug、走通贡献路径，或对比修复前后的测试结果。
5. **编辑草稿**：文档改进、Issue 回复和 PR 评论都先成为草稿，可比较差异、检查风险、保存版本。
6. **确认交付**：确认目标和内容后，由你决定发布到 GitHub，或下载交给其他维护者。

每一步都有独立的产物，可以停在任何一步：没有模型也能做基础体检，没有 GitHub 写入权限也能完成阅读、编辑和下载。

> [!IMPORTANT]
> RepoCare 不会替你做最终决定。AI 结论都标为“建议”，对外发布（回复、评论、创建 Draft PR、修改标签）前必须由维护者确认，这项保护无法关闭；产品也不会自动批准或合并 PR。

## 按角色阅读

**项目维护者**：先读[快速开始](quickstart.md)和[核心概念](concepts.md)，然后按需查阅[功能指南](modules.md)。发布前通读[草稿与交付](drafts.md)。

**协作审阅者**：重点阅读 [PR 检查](pull-requests.md)、[Issue 分诊](issues.md)和[工作流与最佳实践](workflows.md)，理解每条结论对应的提交与证据范围。

**部署管理员**：先完成[部署与运维](deployment.md)和[管理员配置](configuration.md)，再按验收清单检查后台服务、登录、备份与恢复。

## 使用这份手册

- 按 `Ctrl` + `K`（macOS 为 `⌘` + `K`）或 `/` 打开全文搜索，可以搜索功能名称、操作步骤和错误提示。
- 工作区侧栏底部的“使用指南”、首页和登录页顶部的“产品文档”都能打开本手册，未登录也可以阅读。
- 手册以 Markdown 保存在仓库的 `docs/product/` 目录，随代码一起维护；每页右侧都有“在 GitHub 编辑此页”。

手册描述的是当前版本的操作行为。模型结论需要核对；“执行成功”只表示选定的验证步骤完成，不能代替项目自身的完整测试和维护者判断。适用范围见[术语、状态与限额](reference.md#功能边界)。
