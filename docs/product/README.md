# RepoCare 产品文档

RepoCare 帮助 GitHub 项目维护者检查项目资料、处理 Issue、审阅 PR，并把建议整理成可审阅的交付草稿。你可以先完成一次只读体检，再按需要启用模型分析、隔离验证和 GitHub 发布。

## 一次维护的完整路径

连接仓库 → 固定提交进行体检 → 阅读证据 → 分诊 Issue 或审阅 PR → 编辑草稿 → 按需隔离验证 → 人工确认交付。

每一步都有独立产物。报告可以导出，草稿可以保存和下载；没有 GitHub 写入权限也能完成阅读和本地审阅。开始 AI 分析会调用你配置的模型，可能产生服务商费用。

## 按角色阅读

- **项目维护者**：先读快速开始，再按模块查操作；发布前阅读草稿与交付说明。
- **贡献者或审阅者**：重点阅读贡献路径验证、PR 检查和工作流，理解结论依赖的提交与证据。
- **部署管理员**：先完成部署与配置，再检查后台任务、备份和恢复。容器启动成功不代表所有外部服务已可用。

## 如何使用这份手册

站内“使用指南”提供产品文档入口。章节目录用于切换主题，页内目录用于定位步骤；浏览器查找可以搜索当前章。本文档也以 Markdown 保存在仓库的 `docs/product/`，便于离线阅读和随代码维护。

文档说明当前产品的操作行为。模型结论需要核对，执行成功仅说明选定的验证过程完成，不能代替项目自身的完整测试和维护者判断。详细边界见[参考](reference.md)。
