# 工作区设置

工作区设置集中管理四类配置：本地偏好、GitHub 账户、模型连接和项目专属规则。从侧栏底部的“工作区设置”进入；如果是从某个任务跳转过来的，页面顶部会显示“← 返回原任务”，完成配置后可以直接回去。

## 设置模块

| 模块 | 内容 | 保存位置 |
| --- | --- | --- |
| 本地工作区 | 项目显示名、内容语言偏好、是否保留原始内容 | 当前浏览器 |
| 功能说明 | 已集成能力的介绍和使用入口 | — |
| 维护者审核 | 发布前审核的安全边界（始终开启） | — |
| GitHub 账户 | 登录状态、仓库访问与发布权限 | 服务端 |
| 模型连接 | 默认模型、服务地址与连接诊断 | 服务端，密钥加密保存 |
| 项目专属规则 | 项目约定、依据与确认版本 | 服务端，按账户和仓库保存 |

切换模块时，已填写的内容会保留，点击保存后才生效。

## 本地工作区

- **项目显示名**：只用于在本地标识工作区，不会重命名远程仓库。
- **内容语言偏好**：保存分析与草稿的语言偏好，界面本身使用中文。
- **保留原始内容**：翻译时同时保留原文，方便核对技术术语、错误信息和代码片段。

这些偏好只保存在当前浏览器；浏览器禁止本地存储时会提示保存失败，页面上的修改仍然保留。“恢复默认”会恢复并保存默认设置。

## 维护者审核

对外回复、标签变更和文档修改都必须经过维护者确认才会发布。这项设置始终开启，无法关闭。

## GitHub 账户与授权

GitHub 账户有三种状态：

| 状态 | 能做什么 |
| --- | --- |
| 未连接 | 读取公开仓库；不能读取私有仓库，不能发布 |
| 已登录，尚未授权仓库访问 | 从账户中选择仓库；仍不能读取私有仓库或发布 |
| 已授权仓库访问 | 读取你有权限的私有仓库；在你拥有写权限的仓库中发布已确认的内容 |

1. 点击“GitHub 登录”完成 OAuth 登录。
2. 需要私有仓库或发布时，点击“授权仓库访问与写入”。GitHub 的 `repo` 授权范围同时包含读取和写入权限。
3. 授权后，私有仓库仍然受你的账户权限和组织访问策略限制。

> [!NOTE]
> 仓库列表中显示的权限（管理员、维护、写入、读取）是你在 GitHub 上的角色，不代表已经授权 RepoCare 发布。每次发布评论或创建 PR，RepoCare 都会先请你确认。

需要更换账户时点击“退出登录”。注意匿名会话、邮箱账户和 GitHub 账户是不同的身份，数据不会自动合并。

## 配置模型连接

体检的内容研判、Issue 分诊、PR 审查、草稿生成和维护调查都需要模型。没有选择默认模型时，体检仍可运行基础规则，其他 AI 功能不可用。

### 添加连接

1. 打开“模型连接”，点击“新增连接”。
2. 选择**服务类型**。预设会自动填写服务地址和请求协议：

| 服务类型 | 协议 | 说明 |
| --- | --- | --- |
| DeepSeek 官方 | OpenAI Chat Completions | 官方 Key 只配官方地址；中转服务请选“自定义” |
| OpenAI 官方 | OpenAI Responses | ChatGPT 订阅不含 API 凭据 |
| Anthropic / Claude | Anthropic Messages | 填写 Claude API 的模型 ID，不是网页聊天中的名称 |
| Google Gemini（兼容接口） | OpenAI Chat Completions | 使用 OpenAI 兼容接口，不是 Gemini 原生接口 |
| 阿里云百炼 · 北京 / 新加坡 | OpenAI Chat Completions | Key 和模型 ID 需要与地域匹配；Coding Plan 和专属端点请选“自定义” |
| OpenRouter | OpenAI Chat Completions | 填写含提供商前缀的完整模型 ID，使用 OpenRouter 的 Key |
| Ollama 本机 | OpenAI Chat Completions | 连接 RepoCare 所在机器上运行的 Ollama，通常不需要密钥 |
| 自定义 / 中转服务 | 三种协议任选 | Key、协议、模型 ID 和地址必须来自同一服务 |

3. 填写**模型 ID**（必填）和 **API 密钥**。密钥加密保存在本机服务端，保存后不会回显。
4. 自定义服务需要填写 **API 基础地址**：只填平台的 API 根地址，不含 `/chat/completions` 这样的接口路径；必须使用 HTTPS，本机地址可以用 HTTP。表单下方会显示“请求路径示意”，帮你确认最终请求的地址。
5. 第一条连接会自动成为默认；之后新增的连接可以勾选“保存后设为默认”。
6. 点击“创建连接”。

> [!WARNING]
> 修改基础地址但保留旧密钥时，RepoCare 会提醒你确认这把 Key 属于新地址的平台。只向签发 Key 的平台发送它；不确定时请替换密钥。

### 测试连接

保存不会发起模型请求，也不代表配置可用。在连接列表中点击“测试连接”，确认后 RepoCare 会发起少量真实请求，验证文本和工具调用往返（最多 512 个输出 tokens、25 秒）。测试可能产生费用，只测试已保存的版本。

连接卡片会显示“测试通过”“测试失败”或“未测试”，以及“密钥已保存（不代表鉴权成功）”等状态。

### 管理连接

- **设为默认**：之后的 AI 任务使用这份连接。尚未通过测试的连接设为默认时会额外提醒。
- **编辑 / 更新密钥**：更换 Key 时请编辑原连接，不要新建重复连接。同名或同一接口和模型的重复连接会被提示。
- **取消账户默认**：之后的任务回退到服务端环境变量中配置的连接；没有环境变量连接时，体检只做基础规则，其他 AI 功能需要重新选择模型。
- **删除**：历史任务仍然保留。

“最近模型请求诊断”列出本账户最近 5 次模型请求的结果，用于排查失败原因。

### 高级设置

通常无需修改。留空时自动生成连接名称、使用预设值：

- **连接名称**：用于区分账户和用途。
- **请求协议**和**服务商标识**：自定义服务需要匹配平台实际支持的协议。
- **上下文长度 / 最大输出（tokens）**：默认自动模式。填写后作为模型能力声明，不会改变服务商的实际容量。Anthropic Messages 协议强制要求最大输出，自定义模型没有目录值时需要明确填写。

> [!NOTE]
> 无论模型容量多大，工作流本身还有固定上限：单次输入 100,000 字符、草稿文本 30,000 字符、普通请求 60 秒；分诊、PR 审查和文档生成最多 6 轮、12 次只读工具调用。完整列表见[术语、状态与限额](reference.md#处理上限)。

## 项目专属规则

项目专属规则让分诊和审查遵循你的项目约定，例如“Bug 报告必须提供运行时版本”“PR 必须通过 `test` 检查”。

### 规则类型

| 类型 | 用途 | 适用 |
| --- | --- | --- |
| Issue 必填信息 | 某类 Issue 必须提供的字段：运行时版本、操作系统 / 平台、复现步骤、预期行为、实际行为 | Issue |
| 支持的运行时版本 | 允许的运行时与版本前缀，例如 `Python 3.10`、`3.11` | Issue |
| 标签分类 | 把 GitHub 标签（精确匹配）映射到问题类别 | Issue |
| PR 必须检查 | 必须存在的 GitHub 检查名称（精确匹配；旧式 Status 带 `Status:` 前缀） | PR |
| PR 测试变更 | 提醒核对是否有测试路径变更 | PR |
| 项目验证命令 | 项目约定的验证命令，仅作为约定，不自动执行 | 可选 Issue / PR / 两者 |
| 维护约定 | 其他文字约定 | 可选 Issue / PR / 两者 |

### 创建与启用

1. 点击“读取候选并替换编辑区”，从仓库的模板和贡献指南中读取候选规则；也可以点击“添加规则”手动填写。
2. 逐条核对规则类型、显示名称、适用范围和取值。来自仓库的规则会显示来源文件和固定版本，规则含义与必填性由你确认。
3. 点击“保存候选规则”（或“另存为待确认候选”）。此时当前有效的规则继续生效。
4. 勾选“我已核对规则含义、来源与适用范围”，点击“确认启用此版本”。

启用后，新的分析和重试都会使用这一版本；之前的分析不会被覆盖，会标为需要重新分析。确认一个空规则集可以停用现有约束。

> [!TIP]
> 仓库的贡献规范变化后，记得重新核对规则，避免模型按过时的约定评价贡献者。
