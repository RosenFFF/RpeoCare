# PR 分块审查

真实页面 `/pull-requests` 使用 `review-task-store.ts` 保存任务、`review-plan.ts` 划分 Diff、`review-worker.ts` 调用模型并验证发现。维护 Agent Worker 同时处理此队列；结果和控制位于 PR 详情。

## 使用与结果

开始审查时采集 head/base、描述、文件、Checks 和关联需求，固定模型连接与已确认项目规则版本。队列逐块执行，页面展示待审、完成、失败和未审范围。切换页面不取消任务，返回后读取服务端状态。

失败后可重试单块或所有失败块，成功结果保留；停止任务阻止旧 Worker 写入，保留历史结果。人工筛选发现后生成 COMMENT 草稿，部分完成的草稿包含未审范围；活动和过期报告不可生成草稿。

“完成”只表示预算内可见 Diff 已经模型处理，不证明语义正确、测试通过或可以合并。完整文件、部分文件、未审文件、未读取文件分别统计。发现仍校验路径、行号、LEFT/RIGHT 和原文，无有效证据的发现只能作为待核实线索。

## 范围与预算

- 采集前 100 个文件，单文件 patch 最多 120,000 字符，总共 600,000 字符。GitHub 缺失或截断的内容仍未知。
- 按有效统一 Diff 坐标拆分，每块约 5,500 字符，保留原始绝对行号；超长单行明确标为未审。
- 每任务最多执行 32 块，预算外保留未审说明。
- 每次尝试一次模型请求，结构失败至多修复一次。失败不自动重试，单块最多三次人工触发的尝试。传输自动重试关闭。
- 每账户最多三个活动任务、每小时创建三十个；服务端活动队列上限二十个。
- 分块调用使用当前片段、规则、CI 和关联需求，不额外进行源码工具循环；需要跨文件理解时使用详情中的深入核对动作。

## 持久化与版本

SQLite 保存状态、分块结果及加密模型连接。Worker 领取单块，租约三十秒、每五秒续租，写入核对租约和任务状态。中断块标为失败，其他待审块继续；失败块需维护者重试。

每块前及末块后核对 PR 元数据，项目规则版本也参与检查。结果始终绑定采集快照。重试前重新采集并核对完整指纹，版本变化需要新任务。生成及发布草稿校验报告 ID、revision、内容指纹和规则版本。

分块结果、任务状态与汇总报告同事务保存。汇总只合并完成块，对同一发现去重，同任务保留已有人工决定。新任务立即保存待审报告；旧草稿不会被误认为对应新报告。已确认规则单独显示检查依据，也进入审阅草稿，详见 [项目规则](PROJECT_RULES.md)。

实际模型完成率、准确率和交互效果需要当前版本运行验收，不直接沿用旧实验数据。
