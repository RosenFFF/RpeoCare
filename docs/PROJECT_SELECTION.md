# GitHub 登录后的项目选择

## 用户路径

- GitHub OAuth 回调仍进入 `/workspace`。入口先恢复当前项目的成功报告或执行任务；首次 GitHub 登录且没有当前项目时进入 `/projects`。
- 选择仓库后调用现有 `POST /api/workbench`，服务端检查仓库元数据、默认分支和提交是否可读取，再保存当前项目。
- 连接成功进入工作台概览。无报告时提供体检、Issue 和 PR 入口，**不自动体检、调用模型、执行测试或写回 GitHub**。
- 左上角项目切换与首次登录共用 RepositoryChooser；保留手动 URL 和浏览器连接地址草稿。
- 匿名/邮箱用户仍可手动连接公开项目；不同账户数据不会自动迁移。

## 仓库列表边界

`GET /api/workbench/repositories?page=1&affiliation=owner` 需要有效的 GitHub 账户登录，不接受匿名 owner cookie。

- 使用原生 GitHub REST `/user/repos`；未增加第三方服务、付费依赖或额外 OAuth 登录范围。
- 默认展示自己的仓库，可切换到协作者/组织成员可访问的仓库，按最近更新时间降序排列。
- 每页最多 30 条，只请求当前页；下一页依据 GitHub Link 的 next 关系判断。支持第 1–1000 页，最大页不再允许继续翻页。
- **名称/描述搜索和公开/私有筛选仅限当前页**。UI 明示该边界，不冒充全账户搜索；完整 URL 是直接定位其他项目的备用方式。
- 返回经校验的安全 DTO：名称、规范 GitHub URL、有界描述、公开/私有、Fork、归档、所有权及仓库权限。Token 永远不返回浏览器。
- 加载失败可重试或切换手动地址；失败连接不会覆盖已选中的项目。

## 权限说明

普通登录保持 `read:user`，选择公开项目不要求追加写权限。私有仓库需用户自愿走现有 `?write=1` 授权。现有 OAuth 的 `repo` 范围包含读取私有仓库和写入能力，**不是私有仓库只读授权**；UI 明示这一点。

列表权限是 GitHub 对具体仓库返回的权限，缺失时显示“未返回”，与 OAuth scope 是两个概念；项目读取不以发布权限为前置。发布依然需要维护者确认和现有服务端权限、版本校验。组织 SSO、应用访问策略及仓库实际权限可能限制可见列表和私有访问，追加授权不保证可访问所有仓库。

## 验证与限制

单元测试使用临时 SQLite 和 mock GitHub，覆盖认证、查询边界、权限字段、分页、异常响应、入口恢复和连接无自动任务。浏览器验证使用模拟账户/仓库响应，不调用真实 OAuth、模型或发布接口。真实授权上线前仍须配置 GitHub OAuth 并验证组织/私有仓库访问。
