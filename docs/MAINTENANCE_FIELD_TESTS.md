# 公开仓库维护实测：2026-10-17

这批 DeepSeek 实测证明了局部修复、回归拦截和人工核对流程的作用，也暴露了候选代码与计划仍需审阅。它没有证明稳定自动修复、优于通用模型或真实维护者采用。机器记录、实际调用量、指纹和本地证据索引见 [脱敏执行索引](evaluation/2026-10-17-cross-repo.json)。

本文为一次开发实测记录。旧的 [单仓库探索](MAINTENANCE_ACCEPTANCE.md) 保持独立，不合并计算成功率。下文的“实测”指记录中的 Docker 或模型执行；“来源”指固定 GitHub 正文和源码；“待验证”不作为完成事实。

## 执行方式

复用项目已有的 pi SDK、维护工具、SQLite 队列、Git 固定快照、Docker Runner 和 pytest，没有新增执行平台。GitHub 读取使用公开仓库接口，任务和模型写入独立本地数据库，未向上游发布内容，也未把案例灌入用户项目。

初始模型为现有官方 `deepseek-flash` 连接，每例上限为 24 次请求、48 次工具、180 秒，每次输出上限 8192 token。人工反馈后的继续阶段每次另给最多 8 次请求和 16 次工具，累计真实用量见索引。工具和提示在探索中变化，继续阶段不是同条件性能对照；没有把多轮开发调试包装成首次自主成功。

源码通过固定提交目录和 Git blob 获取，缓存前核对字节数及 SHA-1，额外记录输入和实现摘要。独立检查在首次模型调用之前写入并固定 SHA-256，没有把其代码作为 Agent 输入。发现回归后给模型提供了实际错误行为，后续属于人工反馈辅助修订，不能继续称为未见反馈的评测。

Docker 实测环境为 Engine 29.8.2、Python 3.12.3、pytest 7.4.4、Node 24.20.0。Runner 镜像标识为 `sha256:b5b7c87278b9b369ec7832eaf875d79a86ad68b016ccf2747b02ab588fb184b3`。执行断网，根文件系统只读，无额外 capabilities，并限制资源。未执行被检查仓库的宿主命令。

Humanize 固定 Git 树缺少构建生成的 `_version.py`，Runner 也无 hatchling/hatch-vcs。版本 stub 只位于共享测试，不修改生产函数；这不能证明项目构建链有效。其项目声明 pytest 至少 9，而当前使用较低版本，不宣称满足原项目支持环境。

## 计划、范围与人工介入

模型多次把“未运行全套件”“等待人工确认”写进 `missingInformation`，使本可执行的限定检查被锁住。原始任务和计划保持原样。执行者分别记录原计划、人工审阅的限定实验和范围限制，重新通过队列确认执行，没有直接改原计划数据库来伪造模型交付。

python-dotenv 的根目录测试实验与 Humanize 的限定兼容性实验由执行者准备，生产代码仍是模型候选。它们不能计为 Agent 原生方案自行跑通。Humanize 的原任务仍等待补充，实验中的候选失败也没有隐藏。错误的测试预期、缺失依赖和实际生产缺陷分别保留。

直接调用服务端验收脚本覆盖了计划校验、逐条确认参数、队列租约、固定源码、Docker、制品和共享判读函数。没有覆盖浏览器点击、HTTP 确认时最新 GitHub 上下文校验或维护者可用性。此前浏览器自动访问受策略限制，本批没有换通道绕过。

## 从实测修复的问题

以下行为已实现并由对应单元测试或上述实际执行支撑，代码位置为 `src/server/agent`、`src/server/reproduction/executor.ts` 和 `src/shared/lib/maintenance-verification.ts`。

- 候选文件可分页重读，返回当前补丁 ID、版本和未执行标记，避免截断 Diff 成为唯一修订上下文。
- `propose_patch.basePatchId` 支持针对明确候选版本修订，最终 before 仍保留原始提交；过期 ID 拒绝，四文件、三版本和精确替换约束保持生效。
- 执行环境工具说明内置 Runner 的声明、自动模块搜索路径及未知项，不把环境声明当成 Docker 实测。
- 空目录前缀可以浏览根目录；常见 `in_progress` 步骤状态规范为内部 `active`，减少无效工具往返。
- 已缓存或从检查点恢复的源码也核对二进制、疑似凭据及文件大小，评测缓存复用相同规则。
- 额外正常行为若原版全部通过、候选全部出现断言失败，页面、导出及下一步调查明确标出候选回归。已知目标失败优先于另一目标的证据不足展示。
- 并行验收目录带随机 ID，避免同毫秒覆盖；Git 下载与恢复使用命令级长路径选项，解决实际出现的 Windows pack 文件路径过长。

首次执行曾遇到 Runner 镜像缺失、验收目录重名及 Windows 长路径阻塞。对应记录保留，重名目录不进入逐案例结论，修复后重新执行。一次人工实验 manifest 含额外字段被校验器拒绝，修正后独立启动；拒绝不算目标运行失败。

## 复查入口与剩余工作

源码缓存载入由 `scripts/lib/maintenance-pilot-source.ts` 校验，`evaluate-maintenance.ts` 接收显式 `--snapshot=本地快照JSON` 并保留原有历史案例入口。真实调用必须提供 `--run-models`；本批只使用 `--repocare-only`，没有通用模型优劣结论。阶段继续及执行复用已有 `continue-maintenance-pilot.ts`、`execute-maintenance-pilot.ts`；限定双版本实验使用 `accept-maintenance-workflow.ts`。

数据文件、完整日志和独立检查正文留在已忽略的本机 `data/`；公开索引只记录脱敏摘要、相对证据路径及哈希，不含凭据或模型隐藏推理。保有本地制品时可以按索引复查，公共 Git 仓库本身不包含完整重放输入。

后续优先解决范围声明与真正执行前置条件的区分、其他 Python 构建后端和测试依赖准备，以及固定预算下新案例的首次交付稳定性。需要另设未参与开发的案例、预先明确的选择与排除条件，再进行同条件通用模型对照。当前案例不提供维护者采用、节省时间或获奖概率证据。
