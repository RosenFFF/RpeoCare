# Issue / PR 统一收件工作区（2026-10-05）

## 设计依据与选择

参考成熟维护型系统的布局原则，而不是照搬模板：
- GitHub Primer Action List：单列记录，主文本与辅助信息有一致层级，每条记录一个明确动作。
- IBM Carbon Data Table：搜索、过滤、结果统计和批量动作归属于同一个数据工作区；列头明确区分字段。

结合 RepoCare 现有中性灰与深青配色、侧栏与文档工作台，不新增 UI 框架。用响应式 CSS Grid 表达表格式收件列表（记录实际是可键盘操作的 button），不冒充原生 table。全宽列表按数据量自然收缩，详情另行进入全宽工作区；不再组合左右等高面板、PR 卡片网格、自动进入唯一 PR 和巨大空详情。

## 信息结构

### 共同骨架

Issue 使用一个收件工作区组织快捷视图、搜索、筛选、分页和详情。PR 先展示仓库分支目录，选择目标分支后进入同样的筛选与详情流程。分支选择仅改变 PR 浏览范围，不切换整个工作区项目分支。

- 0 条：一个空状态，区分未连接、读取失败、筛选无结果、当前页无记录。
- 1 条：一个全宽数据行，不自动进入详情或调用模型，也没有配套空白详情卡。
- 多条：统一行式结构，不再散成重复卡片；移动端每行分为标题区和紧凑字段区。
- Issue 筛选计数、搜索、分类和批量动作只针对当前 API 页。PR 的相同操作仅作用于选定目标分支的当前页。分支目录搜索只作用于已加载分支，尚有分页时明确提示继续加载。
- 返回详情前的列表，保留筛选、排序及页码并恢复滚动/键盘焦点。

### Issue 维度

问题类型、优先级和处理状态是独立字段。快捷视图提供全部、未分诊、待补充、准备复现、高优先级。类型与优先级优先读取维护者确认值，否则使用 AI 建议；来源可见。未分析不产生正式类别或低优先级结论；导航用标签／标题线索以独立来源明确标记。原文更新时显示过期标记。

批量分诊仅处理当前筛选下的未分诊/过期记录，最多 12 条，不处理被隐藏的其他类型。

### PR 维度

变更类型：依赖更新、文档、缺陷修复、功能、其他。基于标题/标签的轻量规则识别，明确注明非 AI 审查结论。Open 与 Draft 是另一个状态维度，不能和“是否已审查”混同，也不能因 Open 推断可合并。

head SHA 不可读取时显示“待读取”，不编造数量或分析状态。现有 head/base 固定、CI、Diff 证据、结构化发现与人工筛选/版本绑定发布逻辑保持不变。

## 工程组织

- `features/workbench/review-inbox.tsx`：Issue/PR 共用筛选、模式切换和列表交互。
- `features/workbench/maintenance-pulse.tsx`、`issue-work-map.tsx`、`pull-voyage.tsx`：分诊工作地图、PR 分支变更图和证据桥展示。
- `features/workbench/inbox-model.ts`：维度语义及轻量分类规则，纯前端共享定义。
- `features/workbench/issue-visual-signals.ts`：独立的类别线索与可解释关注分，不修改已保存分诊；对应样式在 issue-visual-signals.css。
- `features/workbench/review-inbox.css`：新的列表与详情工作区布局，不依赖旧卡片/双栏覆盖链。
- `git-items.tsx`：保留服务调用与已有详情组件，切换列表/详情，不展示占位详情。

## 验证范围

业务测试覆盖人工确认优先、无数据不虚构分类、PR 类型与 Draft 分离。浏览器覆盖宽屏/窄屏/深色、0/1/多条、错误与空状态区别、筛选/批量范围、返回原筛选和键盘焦点，以及现有分诊、复现和 PR 审查回归。截图数据为测试 fixture，不代表线上用户或真实模型结果。

## 动态维护视图（2026-10-14）

收件工作区默认使用面向维护决策的动态视图，列表继续作为精确扫描与批量处理入口。两种模式共用快捷视图、搜索、筛选、排序、分页和详情跳转，不维护两套状态。

### Issue 分诊工作地图（2026-10-15）

默认入口按下一步动作展示当前页筛选后的 Issue，保留正常字号和响应式布局，不自动缩小所有文字。多个分组时，左侧动作导航提供全部分布与单组聚焦；只有一个分组时直接使用全部宽度。总览显示每组前三条预览（只有一个组时前六条），每条 Issue 的编号定位保留在卡片下方的原生折叠区，默认收起。超出预览的数量有明确说明，点击展开后展示该组全部问题。预览沿用当前排序，空组不占区域，单条区域自然收窄。

首屏复用顶部面包屑识别模块，已连接项目的 Issue 收件页不重复展示大标题，刷新并入搜索筛选工具栏。地图模式省略数量为零或与全部反馈完全重合的非当前快捷项，完整状态与优先级仍可在筛选中选择。工作地图的标题、计数和操作合并为一行，阅读说明按需展开；单组或聚焦时不重复渲染分组标题。主区域使用更宽的可用空间，卡片标题为 16px，宽屏最多三列；内容上移后根据实际视口位置计算可用高度，窗口及工作区尺寸改变时重新测量。窄屏保留页面滚动，不裁切完整内容。

分流仅使用已有字段：原文更新优先进入待重新核对；人工审阅进入待维护者决策；未分诊进入待分诊；待补充信息独立成组；准备复现和待调查合并为待验证与调查，原始状态在依据面板保留；准备回复与已回复分别展示。动作分流不使用标题词表，也不从标题推断优先级、依赖或处理进度，原文更新后的分析明确标记为历史结果。各组表示处理动作，不表示固定顺序或已执行的流转。

问题签显示原始标题、准确评论数、已有优先级及下一步入口。未知评论数不当作零，未知优先级保持待判断。已有 AI 摘要单独标识，短标题或网址形式标题提示核对正文。点击问题打开依据面板，展示完整标题、字段来源、已有摘要或最多 600 字原文预览、缺失信息、分析依据和历史 PR 关联；进入分诊仍使用原有完整详情。关联不证明已修复。图表和依据面板本身不请求模型或写入 GitHub。

探索画布是可选入口，显示当前总览或聚焦范围的全部问题。各区域按自身成员数计算尺寸；滚轮锚点缩放、空白或中键拖拽、按钮与键盘 +／−／0／Home 沿用 use-pr-canvas。返回阅读视图保持分组选择，阅读视图不拦截滚轮进行缩放。两种模式共用上方筛选、排序、分页及最多 12 条的批量分诊范围。

节点和分组均可键盘操作。打开依据后聚焦标题，关闭或按 Escape 后返回问题签；如果该问题不在预览中，则展开编号定位折叠区并返回对应标记。窄屏动作导航换行，依据面板使用可关闭浮层，减少动态效果偏好下关闭过渡与进入动画。详情返回保留现有工作区状态与问题焦点。

### 类别色标与关注分（2026-10-15）

工作地图在操作栏下保留一行可横向浏览的类别色标，颜色、图标与文字同步映射到每张问题签的侧边和类别标记。实线标记表示当前维护者分类确认；虚线表示 AI 建议、历史结果或待确认的标签／标题线索，标记直接注明来源。优先使用维护者分类和已有 AI 分类；均缺失时，精确匹配少量 GitHub 标签别名，再匹配标题词表。多类冲突保留待确认，无明确线索不强制归类。词表线索仅用于导航，不保存为正式分诊，也不推断严重程度。没有增加模型调用或外部标签写入。

类别色标与详细类别筛选共用 review-inbox 的状态，列表也显示相同类别及来源。计数基于当前 API 页在搜索、快捷视图、状态和优先级过滤后的集合，暂不叠加类别自身的过滤；卡片、地图、列表及批量分诊使用同一最终过滤结果。批量仍只处理该结果中未分诊或原文更新的前 12 条。

关注分是可解释的查看顺序规则，满权重为 100。两种视角用于不同维护偏好，不宣称严重程度、修复收益或经统计验证的预测效果。

| 信号 | 维护优先 | 响应优先 | 计算规则 |
| --- | --- | --- | --- |
| 已有优先级 | 45 | 25 | 高／中／低取本项权重的 100%／55%／20%，四舍五入；未知或原文更新后待核对时不计入 |
| 分析时效 | 25 | 20 | 有分析且原文更新时取满权重；分析对应当前原文时取 0；未分析时未知 |
| 讨论量 | 15 | 30 | 权重 × min(1, log₂(1 + 评论数) / 5)，四舍五入；31 条封顶；缺失评论数时未知 |
| 静置时长 | 15 | 25 | 权重 × min(1, 距上次更新天数 / 90)，四舍五入；未来或无效日期未知，不等同无人回复 |

卡片显示已知项之和，+ 表示仍有权重待评估，斜纹部分表示这些未知权重。未知项不作为零风险；分类线索不参与优先级计分。点击问题可逐项展开查看本项得分、权重和计算依据，原文更新或分析中记录的缺失信息也有独立标记。默认按已知关注分排序，同分沿用最近更新；切换维护／响应视角会重新计算并选用关注分排序，仍可改回最近更新或已有优先级排序。浏览器每分钟更新一次用于静置计算的时间，隐藏详情列表时暂停，不请求外部服务。

调研确认，[GitHub Projects 字段](https://docs.github.com/en/issues/planning-and-tracking-with-projects/understanding-fields)已有彩色选项与优先级等元数据，[GitHub AI 分诊](https://docs.github.com/en/issues/tracking-your-work-with-issues/administering-issues/triaging-an-issue-with-ai)与开源 [AI Issue Assessment Commenter](https://github.com/github/ai-assessment-comment-labeler)已支持分析与标签；[Linear Triage Intelligence](https://linear.app/docs/triage-intelligence)已有属性、关联及重复建议，[GitHub 部分 Copilot 自动化](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-automation-rationale-and-approvals)也提供依据、置信度和审批，目前为有适用范围限制的预览能力。因此本轮以类别来源、未知权重、视角切换和动作地图的组合交互作为产品差异，不宣称这些单项能力或该组合全球首创。沿用现有字段、React 和原生样式，无需引入动作服务或图表依赖。

### PR 分支导航与变更图

`pull-branch-atlas.tsx` 从 `/api/workbench/branches` 读取仓库真实分支，包含没有开放 PR 的分支。默认分支、受保护标记和最新提交来自 GitHub。分支目录每页最多 100 个，继续加载按 GitHub Link 分页，最多读取 100 页。目录保留搜索与滚动位置；默认分支不在当前已加载页时提供独立快捷入口。未全部读取时只显示已加载数量，不声明完整目录，也不把未读取 PR 数量写成零。

选择分支后，`git-items.tsx` 通过 PR 列表的 `base` 参数读取计划合入该分支的开放 PR。每页最多 30 条，下一页按钮使用实际分页信号，最多 100 页。切换分支回到第一页，并清除旧分支的搜索、类型和快捷筛选；请求版本与仓库、目标分支、页码绑定，旧响应不能覆盖当前内容。返回全部分支保留目录；现有 `?number=` 深链接仍可直接进入 PR 详情。画布和列表共用同一分支分页结果。

`pull-map-model.ts` 为当前页全部 PR 计算汇流布局，节点以错列阵列展开并连向真实目标分支。每条连线先经过该行上方的布线通道，再进入目标分支主干；节点的文字区域与相邻行保持间距。大页面的目标分支位于初始可见区域附近，主干覆盖完整图面。默认不折叠记录，提供舒展与紧凑两档间距。

`pull-confluence.tsx` 以大圆形节点显示类型图标和 PR 编号，草稿使用圆角方形及明确文字。类型通过标题与标签线索的色标表达，外环独立表示 CI，节点下方保留标题、作者、更新日期、来源仓库拥有者与分支、审查状态、已知文件数和 head 提交。读取文件后显示覆盖范围内的增删行数，未知规模继续标记待读取。类型图例可突出同类 PR 的连线，悬停或键盘聚焦突出单条连线。分类不作为审查结论或严重程度。

分支目录使用与工作台一致的 2D 分支导航，背景、正文、点阵、边线和强调色全部读取现有主题变量，随全局明暗主题切换。每个真实分支对应平面环形标记：默认分支使用青绿色与星形，受保护分支使用主题强调色、虚线轨道与盾形，普通分支使用次级文字色、点线与分支图标；默认分支同时受保护时显示两个文字标记。单个或两个分支采用左图右文的紧凑布局，窄屏改为上下布局；多个分支自动排布并在同一区域滚动。内容高度随分支数量自然增长并设置视口上限，单分支不再撑满整屏。图形不推断继承关系、活跃度、风险或未读取的 PR 数量。已连接项目的收件入口保留紧凑工具栏。PR 画布默认使用原始字号，标题为 17px，节点文字区域宽 256px；超出视口时可以拖动、滚轮缩放或使用编号定位，不自动压缩全部文字。用户可以主动选择「适应全部」查看全景，或使用「原始字号」恢复阅读。图例与编号定位均提供键盘替代操作。Issue 探索画布的默认适应行为保持原有参数。

`use-pr-canvas.ts` 处理鼠标锚点缩放、空白或中键拖拽、缩放按钮和键盘平移。读取证据且几何未变时保留镜头。连线只表达计划合入目标，不推断分支继承、PR 依赖或已经合并。节点大小仅在已知文件数时小幅增加，未知使用固定大小。

分支目录复用现有 GitHub 身份和只读请求器，前后端都核对当前项目。目录及 PR 图不会自动调用模型、逐条读取 Diff 或执行仓库代码。GitHub 无法读取时显示错误，并允许重试；保留的目录明确标为上次结果。目录缺页、未知规模与未知 CI 继续保持未知。

交互参考 [React Flow 的按需展开](https://reactflow.dev/examples/layout/expand-collapse) 和 [Cytoscape.js 的分组图概念](https://js.cytoscape.org/#notation/compound-nodes)。分支导航使用原生 SVG 与 CSS 绘制平面环线、流动线段和圆点，不再载入 Three.js 或依赖 WebGL。动效可手动暂停，也遵循系统减少动态效果偏好；名称、默认与保护标记、提交号及 PR 入口固定在原生按钮中，动画不移动点击区域。页面隐藏、导航不可见及分支离开滚动区域时暂停动画。暂停或禁用动画后仍可正常搜索、通过键盘选择和打开分支。PR 汇流继续使用原有 SVG 与 HTML 画布。分支和 PR 筛选遵循 [GitHub 分支接口](https://docs.github.com/en/rest/branches/branches#list-branches) 与 [PR 列表接口](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests)。

选择节点后点击“读取文件与检查”通过现有只读审查上下文接口读取当前 PR 的文件、CI 和显式关联 Issue，不调用模型。一次仅观察一条，最多缓存 8 份证据；缓存键包含 PR URL、head、base、更新时间及审查快照信号，条目、分析或人工决定变化后重新读取。收起证据、切换节点或卸载会取消未完成读取，响应不匹配列表身份时提示刷新，不覆盖现有条目。每份证据显示读取时间，可显式刷新。

文件改动谱使用同一比例尺表示已读取文件的新增与删除行，默认展示增删总量最多的前 20 个文件。点击柱形查看路径、准确增删数和前 40 行 Patch。文件清单和 Patch 截断分别提示；统计不外推至未读文件。空检查不等于通过，已知失败优先于待执行状态，未知检查状态不被当作进行中。清单不完整时不显示全部完成。旧报告过期与刚读取的新 CI 可以同时存在；上下文接口按 head、base 和内容指纹判断报告有效性，读取过程不改变审查历史。

### 证据桥

服务端列表接口将当前仓库已保存的 PR 审查摘要与 GitHub 列表合并。Issue 节点可显示哪些历史 PR 审查曾明确关联它。PR 选中节点读取证据后展示固定提交上下文中已读取的显式关联 Issue，来源是正文中的同仓库 Fixes／Closes／Resolves 声明。关联不证明修复完成，也不使用标题相似度推断。

动态视图使用普通按钮与语义分组，支持键盘焦点；Issue 默认使用可读的工作地图，可选探索画布，PR 使用画布缩放与全图适应。PR 分支目录使用可读的响应式布局，变更图使用舒展的汇流布局，进入分支或改变图的成员时恢复原始字号。观察面板默认收起，点击节点后显示；窄屏使用可关闭的浮层，画布尺寸保持稳定；`prefers-reduced-motion` 下关闭过渡、展开动画和加载旋转。Issue 工作地图不使用持续扫描或随机运动。

## Issue 详情分诊布局（2026-10-07）

Issue 详情不再把完整分诊和人工维护功能堆在正文右侧，避免短正文与高侧栏形成整列空白。阅读顺序改为：横向分诊摘要 + 准备度/下一步 → 全宽讨论原文/译文 → 维护者确认与维护动作。正文很短时各区域自然收缩；长正文仍可滚动阅读，不人为用占位内容补空白。

首屏保留类别、优先级、置信度、建议动作、摘要和准备度；判断依据/阻塞项、实际/预期/环境、缺失/已有信息/建议标签三个分组采用原生 details 按需展开，不截断或删除分析。不同 Issue 切换时折叠状态重置。正文和主要建议使用14px、表单/动作13px、说明12px，废除详情区原9–10px微字号。下一步动作在准备度卡固定位置显示，不使用悬浮遮挡或嵌套滚动侧栏。

新样式位于 issue-detail.css，均以 issue-detail-layout 为范围，仅作用于 Issue 详情。PR详情、收件列表、复现面板和后端分析/确认/发布逻辑不变。窄屏单列，原文/译文纵向阅读，原生折叠可键盘展开；维护者确认不隐藏，权限和确认规则保留。本文仅记录布局变更，不将AI准备度分数作为真实复现结果。
