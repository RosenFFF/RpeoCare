# 参赛材料核对包

本目录提供与源码、执行记录对应的报告文本和演示脚本，供项目负责人审核。工作区另交付实际页面截图讲解MP4，明确标注非连续录屏。材料不代表已上传赛事平台，也不包含真实维护者采用证明。

- `技术报告.md`：按AI+开源官方参考大纲组织的作品概述、需求方案、AI与资源、实现、验证、开放、风险及总结，身份与分工保留xx占位。
- `撰写依据与核对.md`：区分官方内容要求与通用模板排版参数，逐项核对正文、附录、身份占位和证据边界。
- `演示脚本.md`：JSON Pointer实际流程、截图讲解与后续连续录屏的讲解顺序。
- `第三方资源说明.md`：资源类型、自研边界与仍需负责人确认的许可事项。
- `第三方依赖清单.csv`：由当前锁文件及已安装package元数据整理的完整npm依赖盘点，不等于全部许可义务已经履行。
- `试用任务与记录.md`：首次使用者的任务和事实记录方式；不预填使用反馈。

PDF审阅版位于工作区`作品提交/RepoCare-参赛技术报告-审阅版.pdf`。封面与目录、正文及附件分别编排，正文采用宋体小四、单倍行距，A4纵向、上下2.5厘米和左右3厘米边距。生成版本应在负责人补齐xx信息、核对共同权属、第三方许可、AI工具声明和演示证据后再次冻结。学校名称、学校标识与指导教师信息不进入评审材料。

已知cattrs历史案例的可复查代码与使用说明见仓库`evaluation/cattrs-800/README.md`。这是已参与开发的示例，不作为新的留出样本。

两项受限新任务的首次失败、澄清与用量见[调查预算实测](../MAINTENANCE_BOUNDED_EVALUATION.md)；ItsDangerous原版检查见`evaluation/itsdangerous-126/README.md`。阶段报告成功与模型修复成功分别记录。

JSON Pointer与cachetools两项新输入的首次部分交付、反馈恢复、外部验收和实际页面实践见[交付实测](../MAINTENANCE_RELEASE_EVALUATION.md)。干净安装、依赖审计、回归测试及未验证范围由该文档与[依赖核对](../DEPENDENCY_REVIEW.md)分别记录。完整私人运行数据和模型连接不进入审阅包。
