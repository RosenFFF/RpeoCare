# RepoCare 账号服务接入说明

## 当前实现

首页 `/` 左侧展示交互模型，右侧介绍面板可切换到登录、邮箱注册、找回密码。浏览器前进后退与表单深链接可用。`/login`、`/register` 兼容直接访问。

`src/shared/lib/auth-client.ts` 是尚未配置的适配边界，所有方法返回 `ok: false` 和清楚的提示。它不接收凭证、不调用外部接口。`src/features/auth/auth-panel.tsx` 完成本地必填、邮箱格式、昵称、密码长度与确认密码校验。切换面板时清空表单，演示提交后清空凭证。

这不是可用于生产的认证实现，也没有模拟已登录用户。`/overview` 及其他工作台页面仍是公开的本地示例。

## 启用真实服务时的实施顺序

1. 确定服务端架构与成熟认证库，建立用户、关联 Git 身份、会话的持久存储。服务端身份标识采用提供方与用户 ID 组合，不依赖昵称；账号关联需明确验证，不能仅凭同名邮箱合并。
2. 分别创建 GitHub、Gitee、GitLab OAuth 应用。确定部署域名与各提供方允许的回调地址后再填写回调配置；开发与生产配置分开。客户端密钥只放服务端环境变量，禁止 `NEXT_PUBLIC_` 暴露。优先申请登录必需的最小 scope；访问项目仓库另行授权。
3. 在服务端实现授权发起和回调，使用认证库校验 state，并按提供方能力启用 PKCE。回调成功后签发安全的 HttpOnly 会话 Cookie。持久化令牌需受保护，前端不能直接持有 OAuth 客户端密钥。
4. 配置邮件提供商、发信域名和验证 / 重置链接。邮箱注册需服务端校验、可靠的密码哈希、限流、短期单次验证令牌；重置流程避免泄露账号是否存在。邮件链接目标由服务端固定配置。
5. 替换适配方法的请求与返回类型，再让表单把必要输入提交到服务端。实现待处理、失败、重试、已发送、验证成功、退出等真实状态；不能只把 `configured` 改为 `true`。
6. 为真实工作区及 API 增加服务端会话与仓库权限校验。保留独立演示入口，区分示例仓库和真实用户数据。
7. 用实际测试账号逐一验证三种 Git 授权的成功、取消、过期、回调异常；验证邮箱注册、邮件送达、链接过期、重复注册、重置和退出。通过后移除“尚未开通”提示。

当前仓库不包含任何 OAuth 密钥、邮件密钥或预设回调 URL。单靠前端页面无法完成真实授权与邮箱验证。
