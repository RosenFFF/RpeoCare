# 模型连接配置与交互边界

## 为什么会出现三份同名连接

旧界面默认展示新增表单；用户再次填写而未点击“编辑”时，POST 不带 id，服务端执行创建。首条连接自动成为默认，之后新增不会替换默认。记录允许同名/同目标，卡片又缺少端点与编号区分，导致误以为新 Key 已更新旧默认。无法从数据断定是重复点击还是多次主动新建，但代码明确缺少重复创建保护。

## 新版界面

- 顶部显示实际默认名称、模型、协议与端点，提供“编辑当前默认”；明确作用于之后的 AI 任务，排队体检保留快照。
- 已保存列表显示短编号、配置版本、默认标记、端点、密钥是否保存和测试状态。旧同名/同目标项提示重复，不自动删除、合并或选择别人的凭据。
- 表单只在点击新增/编辑后出现。编辑带 id+revision；新增标题/保存按钮明确创建。保存返回精确 savedId，不通过列表末尾猜新记录。
- 保存后可明确勾选设为默认，与保存原子完成；不勾选不切换（只有第一条自动默认）。单独设默认/删除有目标编号确认，删除当前默认说明回退影响。
- 首屏只保留服务类型、模型 ID 和 API Key；自定义 / 中转服务还需填写 API 基础地址。预设自动带入地址与协议，名称自动生成，上下文和最大输出使用自动模式。
- “更多设置”收起可选连接名称、预设地址覆盖、请求协议、上下文与最大输出、服务商标识及请求路径示意；不展开时按预设和自动模式保存。编辑已保存连接时默认保留密钥，可单独选择替换或清除。
- 表单使用分隔线与字段层级，不再叠加默认模型色块、内嵌表单卡片和多层灰底；新增时只保留一个入口，编辑时隐藏页头入口，空配置正在编辑时不重复展示空列表 CTA。首条连接自动成为默认，不展示无效的默认选择框。
- 九个预设：DeepSeek、OpenAI、Anthropic、Gemini OpenAI兼容、百炼北京/新加坡、OpenRouter、Ollama本机、自定义/中转。预设来自官方接口说明，**不是逐平台真实调用认证**，不自动查询模型、不固定容易过时的模型名称、不宣称所有参数与工具都通用。
- OpenAI 预设采用 Responses，可手动切 Chat Completions；Gemini、百炼等明确用兼容协议，本轮不新增 Gemini 原生协议。百炼普通API与Coding Plan分开说明；Ollama本机指服务所在主机，不自动安装。
- 请求路径示意是根据协议拼接，不是联网测试；中转 Key 与官方地址不混用。修改基础地址并保留旧密钥前需确认发送目的平台。
- 密钥默认隐藏，只可显示本次输入；旧密钥不返回、不放浏览器存储，切服务类型清空输入并要求对应Key。Ollama默认无Key；远程不使用Key可保存但真实调用会拒绝缺少凭据，不假称可用。
- 离开/刷新/切表单有未保存确认。测试按钮二次说明少量请求可能计费、只测保存版本、不切默认；不自动调用模型。

## 前后端防重

客户端用同步 ref 锁防连续提交，目标/名称重复时提示编辑已有；服务端事务检查同账户规范化名称、接口/协议/模型。新建同名一律拒绝；同目标不同名默认拒绝，只有显式 allowDuplicate 允许另账户/用途。不解密比较Key来推断账户，不跨账户合并。旧重复项可原位更新密钥并重命名，不强迫删数据。DeepSeek官方 / 与 /v1 按文档归一，其他自定义路径不乱合并。revision仍拒绝旧版本覆盖。

## 参考与验证

参考 Open WebUI、Cherry Studio 的服务配置组织方式及各平台官方地址说明，保留 RepoCare 现有主题/原生控件，不复制第三方整套界面、不新增UI依赖。业务测试使用临时DB/mock，浏览器测试用假配置和假Key。没有测试用户真实密钥、切换现有默认或删除那三条历史连接。


## 上下文与最大输出：自动或自定义（2026-10-07）

两项允许正整数或 null，UI 留空即 null，新连接默认留空；已有保存数值不做静默迁移，点击“清空两项，使用自动模式”并保存才生效。取消旧的 4,000,000 / 200,000 产品数值上限，仅校验正整数、安全整数范围及两项均填时输出不大于上下文。

- **上下文**：填写值用于 pi Model 的 contextWindow 元数据；它不是服务商参数、不扩大模型容量、也不是精确 token 计数。留空时仅使用完全匹配的 SDK 模型/协议/端点目录元数据；自定义未知模型使用0表示未知，不编造“无限上下文”。当前 pi-agent-core 集成不自动 compaction，不保证主动准确裁剪到此值；服务商仍校验真实容量。
- **最大输出**：普通 assistant 与 Audit Agent 统一使用用户值，不再压到4096/3500。Chat Completions / Responses 自动模式通过 onPayload 移除 pi-ai simple wrapper 注入的默认 output-token 字段，避免SDK默认32k被误认为“没有额外限制”；服务商自己的默认与能力上限仍生效。
- **Messages例外**：Anthropic强制 max_tokens。用户明确值优先；留空仅使用完全匹配SDK目录 maxTokens。未知自定义模型必须填写，报可操作配置错误，不偷偷补巨大数值。
- 模型目录是本机SDK版本的数据，不宣称实时查询到服务商最新能力。推理可能消耗服务商输出预算；length结果不等于网络/授权失败。
- 只修改这两个tokens字段。输入100,000字符、草稿30,000字符、请求60秒、Agent7轮/18工具/90秒/24,000报告字符、快照分页及结构/安全校验仍保留，在独立可展开“仍保留的边界”中显示。连接测试用512输出tokens/25秒，不是正式生成预算。
- 用户调整只作用于新请求。已排队体检配置快照（含 null）保持一致；不删除模型连接、不换默认、不调用真实模型或增加自动重试。

验证使用临时DB和mockSDK/provider：自动字段读写、保存版本与队列快照、匹配目录/未知元数据、Messages例外、普通任务8192和Agent16384透传、真实SDK请求payload不带三个输出token字段。不是仅测UI空输入；不消费真实用户Key额度。
